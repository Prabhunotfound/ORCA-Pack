# ORCA-Pack : Order-Robust Capacity Adaptive Packing

Task-incremental continual learning on Split-CIFAR-100 (10 tasks x 10 disjoint classes) with a ResNet-50 Backbone.

PackNet, PiggyBack and EvE are implemented as baselines and compared with ORCA-Pack (adaptive capacity, smart pruning, fair-share reservation, task-ID router).

## Repository structure

```
├── notebooks/
│   ├── Preprocessing.ipynb
│   ├── PackNet.ipynb
│   ├── PiggyBack.ipynb
│   ├── EvE.ipynb
│   ├── ORCA-Pack.ipynb
│   └── ORCA-Pack_PiggyHybrid.ipynb
├── README.md
└── requirements.txt
```

| Notebook | Description |
|---|---|
| `Preprocessing.ipynb` | Builds the 10 tasks, the validation split and the task orders. Run once, locally. |
| `PackNet.ipynb` | Iterative magnitude pruning, prune ratio 0.5 per task. |
| `PiggyBack.ipynb` | Frozen backbone with a learned binary mask and head per task. |
| `EvE.ipynb` | Adaptive per-layer allocation between consecutive tasks (without H2 selection). |
| `ORCA-Pack.ipynb` | ORCA-Pack : PackNet-based with smart pruning, fair share and a task-ID router. |
| `ORCA-Pack_PiggyHybrid.ipynb` | ORCA-Pack and PiggyBack hybrid. |

## Setup

Python 3.12 (the notebooks were run on Python 3.12 and 3.13).

```bash
git clone https://github.com/Prabhunotfound/ORCA-Pack
cd ORCA-Pack
pip install -r requirements.txt
```

The model notebooks need a CUDA GPU and were run on Kaggle.

## Data

The data is not stored in this repository. It is generated by `Preprocessing.ipynb` only.
Running it downloads CIFAR-100 and writes the processed data below.

```
Data/
├── raw/
└── processed/
    ├── task_order.json (6 task orders)
    ├── task-1/
    │   ├── train/data.npz
    │   ├── valid/data.npz
    │   └── test/data.npz
    ├── task-2/ ...
    └── task-10/
```

Each **data.npz** contains:

| Key | Type | Shape | Meaning |
|---|---|---|---|
| **images** | uint8 | (N, 32, 32, 3) | raw pixels, not normalised |
| **labels_local** | int64 | (N,) | label 0-9 within the task |
| **labels_global** | int64 | (N,) | original CIFAR-100 label |

Every task has 4500 train, 500 valid and 1000 test images.

### Kaggle dataset

The contents of `Data/processed/` (not `raw/`) are uploaded as a Kaggle dataset:

**https://www.kaggle.com/datasets/prabhanshu22/dl-dataset/data**

In a Kaggle notebook, add it under Input. It is mounted at `/kaggle/input/datasets/prabhanshu22/dl-dataset/`.
Run `!ls /kaggle/input` once to confirm the name and set `DATA_DIR` in the config cell of the model notebooks.

Note : Do not rerun `Preprocessing.ipynb` after the dataset is uploaded. The task difficulty probe depends on hardware, so regenerating the data can change `task_order.json`.

## Execution order

| Step | Notebook | Where | Output |
|---|---|---|---|
| 1 | `Preprocessing.ipynb` | Local | Data/processed/ (10 tasks, task_order.json) |
| 2 | `PackNet.ipynb` | Kaggle (GPU) | accuracy matrix and metrics for PackNet |
| 3 | `PiggyBack.ipynb` | Kaggle (GPU) | accuracy matrix and metrics for PiggyBack |
| 4 | `EvE.ipynb` | Kaggle (GPU) | accuracy matrix and metrics for EvE |
| 5 | `ORCA-Pack.ipynb` | Kaggle (GPU) | ORCA-Pack results, with the task-ID router |
| 6 | `ORCA-Pack_PiggyHybrid.ipynb` | Kaggle (GPU) | ORCA-Pack and PiggyBack hybrid results |

1. Run step 1 once, then upload `Data/processed/` as the Kaggle dataset `dl-dataset`.
2. Steps 2 to 6 only depend on that dataset, not on each other, so they can be run in any order.
3. Before running a model notebook, attach the dataset and check `DATA_DIR` in the config cell.
4. For order robustness, set `ORDER_ID` to 0, 1, 2, 3, 4 and 5 in the config cell and rerun steps 2 to 6.
